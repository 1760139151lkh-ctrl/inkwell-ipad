## The recording view (§6.12), the part to react to most

A right-side **Recordings panel**, opened with the waveform button top-right. You can also open it by
tapping the recording bar's timer or the playback bar's ⋯. The page stays visible; it re-fits to the narrower column.

- **Top:** the note's recordings (play glyph · name · duration · date/time · ⋯ Rename / Transcribe / Delete).
  While recording, this becomes a live card: big timer, level meter, Stop.
- **Middle:** the transcript of the selected recording, with timestamps. During playback the current line
  is highlighted, the list follows the playhead across recordings, and **tapping any line seeks there**
  (the same seek as tapping ink). While recording, finals appear solid and volatile text dimmed/italic.
- **Bottom (pinned):** whole-note scrubber with recording-boundary ticks, −10/+10, play/pause, speed.
- This replaces Notability's playback ⋯ popover **and** its Transcripts tab.

## M3-5 timestamp survival (§7.2)

- Lasso move (a stroke transform) and serialization (copy/paste, save/load): `creationDate` survives (unit test).
- Partial erase: a repair path is in place (`CanvasController.repairEraserTimestampsIfNeeded`). If split pieces
  ever get a fresh date, they inherit the original stroke's date by bounds overlap.
- **Still needs a real-Pencil check on your iPad:** partial-erase a timed word, then play and confirm the
  pieces still fade in at the right moment.

## Decisions I made (easy to change)

1. **Portrait library slides over the note** instead of squeezing it, because a 564 pt editor column can't fit the toolbar. Landscape keeps Notability's three columns.
2. **Recordings button (waveform) in the top-right chrome**, next to ⋯ and Pages. Record and Play sit side by side in the main toolbar (the PRD's one intentional deviation).
3. **Playback bar has an ×** to leave replay mode (ink back to full opacity).
4. **Audio is captured as PCM `.caf`, then transcoded to AAC `.m4a` on stop.** An `.m4a` file isn't readable until it's closed, so a crash would lose it; a `.caf` survives. That's what made crash recovery work.
5. Audio uses the mic's native sample rate (48 kHz on iPad) instead of 44.1 kHz, to avoid resampling on the tap thread. It's still mono, at 64 or 128 kbps.
6. The SwiftData `Divider` model is named `SubjectDivider`, because `Divider` collides with SwiftUI's view.

## Known limitations (§7.6)

- In the Simulator, `SpeechTranscriber` isn't available, so the app uses the `DictationTranscriber` fallback
  (shown in Settings › Audio). On an iPadOS 26 iPad it should use `SpeechTranscriber`.
- No speaker labels, no custom vocabulary.
- The Simulator can't test Pencil pressure, double-tap, or palm rejection. These need your iPad.

## Regenerate

```bash
cd Inkwell && xcodegen generate
xcodebuild -project Inkwell.xcodeproj -scheme Inkwell -destination 'platform=iOS Simulator,name=iPad Pro 13-inch (M5)' -derivedDataPath build/DerivedData build
xcrun simctl install booted build/DerivedData/Build/Products/Debug-iphonesimulator/Inkwell.app
../review/capture.sh 06-editor-ink editor-ink        # any INKWELL_SCREEN value from DemoSeeder.applyLaunchState
```

Demo audio in `demo-assets/` is macOS `say` output. The handwriting font is EMS Felix (SIL OFL), used only by the debug seeder.
